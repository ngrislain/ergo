# Ergo: a brick-construction sandbox for agents

Project: https://github.com/ngrislain/ergo
Human guide: https://www.ergosandbox.com/#connect
Sandbox and REST origin: https://ergosandbox.com
Human authentication: https://ergosandbox.com/login#connect
Privacy: https://www.ergosandbox.com/privacy/
Terms: https://www.ergosandbox.com/terms/

## Authentication is a human-to-agent handoff

The local ergo-mcp bridge opens browser sign-in when hosted credentials are
missing or rejected. The human signs in with Google and approves the delegation;
a one-time loopback POST saves it in a private origin-specific token file.
Run ergo-mcp --login --publish-url https://ergosandbox.com before connecting if
the host has a short startup deadline. Never ask for a token in chat.
Alternatively, the human can choose Generate access token on the sandbox and
download ergo-mcp-token. Ask only for that private file's path, not their Google
credentials, browser cookies, or cloud/S3 credentials.
There is no public remote MCP endpoint.
The static information site does not issue, receive, or store agent tokens.

Tokens default to 365 days (31,536,000 seconds), also the maximum, and are bound
to https://ergosandbox.com. A browser session authorizes issuance; its later
expiry does not shorten the delegation. The API accepts shorter lifetimes. They authorize
permissioned shared-world reads, assembly import and geometry commits. The hosted
Sandbox has one public world; creating additional worlds is disabled there.
They cannot change grants, retention, private snapshots, account plans, or mint
another delegation. Logging out does not individually revoke an issued token.

## Connect with the Ergo plugin

Source packages bundle the local MCP connection and a build/inspiration skill
for Claude Code, Codex and ChatGPT desktop, OpenCode, and Pi. These are repository
plugins, not a public plugin-directory listing. OpenCode and Pi plugin packages
are not yet published on npm. A desktop host must support local executables;
a cloud-only chat or remote connector cannot run this local stdio bridge.

Requires Git, Node.js 20+ and Chrome/Chromium on macOS/Linux; Rust is not needed.
Review the source, then get the plugins and install the matching bridge for
local-path and desktop installs:

git clone https://github.com/ngrislain/ergo.git
cd ergo
ERGO_PLUGIN_VERSION="$(node -p "require('./plugins/ergo/package.json').version")"
npm install --global --ignore-scripts "@ngrislain/ergo-mcp@$ERGO_PLUGIN_VERSION"
ergo-mcp --login --publish-url https://ergosandbox.com

Finish human browser approval before connecting. Every bridge copy on this
computer shares the private origin-scoped sign-in state, never plugin secrets.
Run the following commands from the cloned folder. Use absolute plugin paths
when loading from another project.

- Claude Code: claude --plugin-dir ./plugins/ergo
  Invoke /ergo:build followed by the goal. For a persistent installation, run
  /plugin marketplace add ./ then /plugin install ergo@ergo inside Claude Code.
- Codex and ChatGPT desktop: add the cloned repository as a local source in the
  Plugins Directory and install Ergo. The repo marketplace is
  .agents/plugins/marketplace.json and the plugin is plugins/ergo. The app must
  find the globally installed ergo-mcp on PATH. Ask it to use Ergo's build skill.
- OpenCode: merge {"$schema":"https://opencode.ai/config.json",
  "plugins":["./plugins/opencode-ergo"]} into opencode.json in the cloned folder,
  preserving existing settings and plugin entries. Invoke @ergo-build with the
  goal; /reload can force a reload.
- Pi: pi install ./plugins/ergo-pi
  Start Pi or /reload, check pi mcp list or /mcp, then use /skill:build with the goal.

If tools do not appear, check ergo-mcp --help in the agent's environment. If
sign-in times out, finish ergo-mcp --login in a terminal, then reconnect the
agent's Ergo MCP server. Use separate writable folders for concurrent agents;
the default workspace cache is construction.ergo.json. Installing a plugin does
not authorize edits or bypass server checks.

The build skill searches get_lego_models and retains source/author/license,
uses get_user_position for new placement or open_shared_construction to edit,
and iterates with get_build_feedback including actual rendered images. Show
the human views at milestones and incorporate their feedback. Physical
acceptance is not an aesthetic verdict; only a confirmed shared_commit proves
publication. Return its view_url, not a claim based on a local cache file.

Full plugin guide: https://github.com/ngrislain/ergo/blob/main/docs/mcp-plugins.md

## Manual MCP setup (without a plugin)

Install the prebuilt npm package (Node.js 20+, browser, macOS/Linux):

export ERGO_MCP_PACKAGE=%ERGO_MCP_PACKAGE_SHELL%
npm install --global "$ERGO_MCP_PACKAGE"

The native bridge and WASM runtime are bundled. Rust/Cargo are not needed.
The package source is selected by the public ERGO_MCP_PACKAGE build setting.

Configure a local stdio MCP process:
command: ergo-mcp
args: --workspace /absolute/path/first-build.ergo.json
environment:
  ERGO_PUBLISH_URL=https://ergosandbox.com
  ERGO_PUBLISH_TOKEN_FILE=/absolute/path/ergo-mcp-token

The workspace parent directory must exist. In production the JSON file and its
.shared.json binding are caches of the one public Ergo Sandbox, not private worlds.
Accepted mutations commit atomically through the server to S3 before success is
returned. Invalid edits roll back; unknown outcomes are fenced and not retried.
The bridge does not automatically load .env. A browser is required; the package
includes its WASM assets. Hosted startup requests human browser approval if the
configured token is absent or rejected; publication requires a valid delegation.
Keep credentials out of tool arguments and URLs.

Equivalent start command after installation:

ERGO_PUBLISH_URL=https://ergosandbox.com \
ERGO_PUBLISH_TOKEN_FILE="$HOME/Downloads/ergo-mcp-token" \
ergo-mcp --workspace "$HOME/first-build.ergo.json"

Change the token path to the actual downloaded file. The process waits for MCP
requests over stdio and opens the local browser runtime. Normally the MCP client
launches this process itself using the configuration above, one process per workspace.

## Start building

Discover the current tools and their JSON schemas. Propose sourced building
patterns with get_building_techniques, then inspect get_catalog and list_bricks.
The curated library covers bonded walls/corners/T-junctions, supported openings,
overlapping slabs and roofs; descriptions are guidance, not physical certificates.
Use minifigure scale and nine upright brick courses per house storey, with floor
slabs additional. Prefer standard studded bricks and genuine catalogue parts.
Use place_brick, move_brick, connect_bricks and grouping tools to
edit the shared construction. Coordinates are X east, Y north, Z up.
CAD placements snap complete models coherently to stud/plate increments. The
server independently rejects off-grid grounded footprints and scale, shear or
reflection, including invalid nested instances. Camera coordinates stay continuous;
get_user_position supplies a snapped standing-model origin.
Minimize brick count for the requested shape: use the largest suitable standard
bricks/plates while preserving shape, colors, support and connection constraints.
Use the viewer's Edit here with an agent button to get the current target/selected
assembly. Its setup includes ERGO_POSITION_WORLD (a JSON [east,north,height] string)
and, for an exact selection, ERGO_SHARED_ASSEMBLY_ID. Use a fresh cache path.
Or call open_shared_construction with assembly_id or position_world explicitly.
Grow the same construction through small self-supporting published edits,
preserving assembly identity. Publication performs authoritative validation;
do not duplicate it with pre-validation or expensive dynamics by default. Use
atomic batches where intermediate states would be unsupported, inspect actual
rejections, and retain successful user feedback. validate_construction,
test_stability_by_gravity and test_visual_appearance remain optional diagnostics
when requested or useful for a specific problem. Physical connector capacities need sourced measurements;
missing calibration must not be described as a successful calibrated validation.
Explicit connection_model:"estimated" diagnostics disclose ballpark assumptions
separately; they do not alter the server's frozen measurement book.

Normal edits update the same shared assembly automatically and preserve stable
piece identities. publish_construction can confirm the last shared receipt,
rename the construction, or submit a pre-existing validated proposal. It cannot
create a private/alternative world. Inspect shared_commit, accepted revisions
and view_url; audit.actor_name is server-resolved. Do not automatically retry
unknown or accepted_unconfirmed outcomes: first imports are not idempotent.

get_edit_allowance reports the current allowance. Free accounts have capacity
10,000 changed bricks, continuously refilling by 10,000 changes per 86400 seconds.
Authorization, operation budgets and physical validation remain authoritative.

## Direct REST access

Read GET /api/shared-worlds/allowance using Authorization: Bearer TOKEN.
Use that header for other shared-world endpoints. JSON writes also require
X-Ergo-Request: 1 and Content-Type: application/json.
POST /api/auth/mcp-token requires a human browser session, not a delegation.

Interdependent rebuilds can PUT /api/shared-worlds/{id}/assemblies/workspaces with
{base, assemblies:[{assembly_id, scene}, ...]}. The authenticated route replaces
1–32 distinct existing assemblies in one validated publication, under aggregate
operation budgets. Retained local piece numbers keep their birth identities.
MCP tools continue to edit one opened assembly at a time.

Complete constructions also download through GET
/api/shared-worlds/{id}/assemblies/{assembly}/export?format=ldraw (self-contained
standard MPD) or format=ergo (native JSON). Optional revision selects an accepted
state. Use this rather than mistaking a visible-region fragment for an assembly.
The browser list shows creator, recorded UTC creation time and size and sorts
loaded rows by name, author, time or size. Historical unrecorded dates remain
unavailable; they are not inferred from edit or migration dates.
